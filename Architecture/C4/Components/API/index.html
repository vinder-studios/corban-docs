SmartCorbans — Componentes da API

A API SmartCorbans aberta: 12 módulos de domínio que agrupam os 32 módulos de produto, os componentes de entrada (endpoints, tempo real, webhooks) e os de suporte. O Worker hospeda os mesmos módulos e executa os jobs que eles registram. Decisões em ADR-0012 a ADR-0015.

As escritas seguem o fluxo do negócio (Marketing → Leads → Créditos; Leads → Propostas → Clientes). A única seta de volta, Acesso → Leads na inativação de usuário, passa pelo contrato de Leads. Isso resolve a dependência de arquitetura registrada em Admin · Usuários (RN-USR-05).

Regras de fronteira

  1. Cada módulo é dono das suas tabelas, num schema próprio do PostgreSQL.
  2. Módulos se falam pelo contrato público do outro, no mesmo processo, via o projeto Contracts.
  3. Efeitos colaterais por evento de domínio, por exemplo "Proposta paga" → Desempenho e Clientes.
  4. Sistemas externos só via Adaptadores, atrás de interfaces definidas pelos módulos.
  5. Escopo em duas barreiras: Endpoints decidem a ação, a Persistência filtra os dados (RNF002).

Decisões deste nível

  • ADR-0012 · EF Core com Npgsql, um DbContext por módulo, com filtro global de escopo e transação compartilhada entre contextos.
  • ADR-0013 · CQRS com MediatR 12.x, também para os eventos de domínio. Versão fixada em 12.x, a última com licença Apache 2.0.
  • ADR-0014 · Módulo é uma pasta, com um projeto por camada: Domain, Application, Infrastructure e Contracts. Application → Domain; Infrastructure → Application e Domain; outro módulo → só Contracts. O isolamento é garantido pelas referências entre projetos.

As premissas do nível 2 viraram as ADR-0005 a ADR-0011.
