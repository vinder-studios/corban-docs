SmartCorbans — Containers

A caixa do SmartCorbans aberta: três aplicações web, uma API, um Worker, o banco de dados e o armazenamento de arquivos, e como eles falam com o Keycloak, a Huggy, o AbacatePay, o ViaCEP e a API do Banco Central. As escolhas de tecnologia deste nível estão decididas nas ADR-0005 a ADR-0011.

Containers

ContainerTecnologiaResponsabilidade
AdminSPA · React 19, Vite · NetlifyConfiguração da estrutura da operação (15 módulos). Só apresentação: a regra vive na API. Recebe notificações em tempo real; o sino é único entre as três aplicações (ADR-0025).
CRMSPA · React 19, Vite · NetlifyOperação comercial das Lojas (14 módulos). Conexão em tempo real com a API para o Chat e notificações.
MarketingSPA · React 19, Vite · NetlifyProspecção, Carteira Ativa e Dashboard. Envia as Listas (CSV/XLSX) para a API. Recebe notificações e mudanças de estado pelo tempo real (ADR-0015).
API SmartCorbansASP.NET Core · .NET 10* · AzureÚnica porta de entrada das três aplicações, inclusive para o login: recebe as credenciais e autentica no Keycloak. Permissões e isolamento entre Lojas, cadastros, Funis, motor de Simulação, distribuição em duas camadas, Créditos, Propostas e Metas. Recebe os webhooks da Huggy e do AbacatePay e publica eventos em tempo real para o CRM.
Worker.NET Worker Service* · AzureTudo que roda fora de uma requisição: Varredura Recorrente às 00h, pré-análise em lote, importação de Listas, injeção de Leads aprovadas respeitando o limite diário, virada do Limite de gasto diário.
Banco de dadosPostgreSQL · AzureFonte única dos dados de negócio, Extrato append-only, trilha de auditoria e fila de jobs. Não guarda mensagens do Chat (Huggy) nem credenciais (Keycloak).
Armazenamento de arquivosAzure Blob Storage · AzureLogo da Loja, Documentos do Cliente e da Proposta, arquivos de Lista e da Lista de bloqueio. Privado: a API confere a permissão e gera uma URL assinada de curta duração, e o navegador envia ou baixa direto (ADR-0024). O Worker lê os arquivos de Lista.

O Shell não é container: sidebar, header, app switcher e menu da conta são pacotes do monorepo compilados dentro de cada aplicação.

Decisões que o diagrama segue

  • Instância única: uma API e um banco; Lojas separadas por regra, não por infraestrutura (RNF002).
  • Monorepo pnpm + Turborepo com três SPAs e Shell em pacotes compartilhados.
  • Keycloak sem FeijucaAuth (D-07); só a API fala com ele.
  • D-09 · Login pela API: a tela de login envia as credenciais à API, que autentica no Keycloak.
  • D-10 · PostgreSQL.
  • D-11 · Hospedagem: backend na Azure, aplicações na Netlify. Domínios diferentes, então a API habilita CORS para as três.
  • Chat não persistido: a API repassa, não armazena.
  • Um só motor de Simulação (RN-SC-03), usado pela API e pelo Worker.
