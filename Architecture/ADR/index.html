Registro de Decisões de Arquitetura (ADR)

Todas as decisões estruturais que sustentam a construção e operação do SmartCorbans. Cada decisão é imutável após aprovação, registrando motivação, alternativas rejeitadas e critérios formais de revisão.

ADR-0001 Frontend / Autenticação Aceita

Keycloak atual como provedor de identidade, sem a FeijucaAuth

O SmartCorbans usa o mesmo Keycloak e a mesma base de identidade de hoje, falando com ele diretamente, sem a FeijucaAuth.

Origem: D-01 e D-07 (`C4/01-contexto.md`) — ADR retroativa Ler Decisão
ADR-0002 Frontend / Autenticação Aceita

Login pela API, com a tela própria do Shell Público

A tela de login envia e-mail e senha à API, que autentica no Keycloak e devolve os tokens. As aplicações web não falam com o Keycloak.

Origem: D-09 (`C4/02-containers.md`) — ADR retroativa Ler Decisão
ADR-0003 Dados & Armazenamento Aceita

PostgreSQL como banco de dados

O banco é PostgreSQL, num único servidor, com um schema por módulo. O SmartCorbans não usa MongoDB; o MongoDB atual é só a origem da migração.

Origem: D-10 (`C4/02-containers.md`) — ADR retroativa Ler Decisão
ADR-0004 Frontend / Autenticação Aceita

Backend na Azure, aplicações web na Netlify

API, Worker e banco na Azure; Admin, CRM e Marketing na Netlify. Os serviços específicos da Azure estão no diagrama de implantação, como premissas (P-12 a P-18).

Origem: D-11 (`C4/02-containers.md`) — ADR retroativa Ler Decisão
ADR-0005 Backend & Aplicação Aceita

Backend em .NET 10, com Clean Architecture e CQRS

API e Worker em .NET 10 (ASP.NET Core e Worker Service), com Clean Architecture e CQRS.

Origem: P-01 (`C4/02-containers.md`) Ler Decisão
ADR-0006 Backend & Aplicação Aceita

Uma API em monolito modular

Uma única API, organizada como monolito modular: os 12 módulos rodam no mesmo processo e no mesmo deploy, separados por fronteiras explícitas no código.

Origem: P-02 (`C4/02-containers.md`) Ler Decisão
ADR-0007 Backend & Aplicação Aceita

Worker em processo separado, com o mesmo código de domínio

Um Worker em processo separado da API, hospedando os mesmos módulos de domínio (ADR-0006).

Origem: P-03 (`C4/02-containers.md`) Ler Decisão
ADR-0008 Dados & Armazenamento Aceita

Fila de jobs no próprio PostgreSQL, sem broker

Os jobs ficam numa tabela do próprio PostgreSQL, sem broker de mensagens.

Origem: P-04 (`C4/02-containers.md`) Ler Decisão
ADR-0009 Backend & Aplicação Aceita

API com réplica única, sem escalonamento automático

A API roda com uma réplica fixa: mínimo 1, máximo 1, escalonamento automático desligado.

Origem: revisão da seção de escala de `C4/04-implantacao.md` (substitui "2+ réplicas com afinidade de sessão") Ler Decisão

Tempo real com SignalR na API, sem backplane

Tempo real por WebSocket com SignalR, hospedado na própria API, sem backplane.

CQRS e eventos de domínio com MediatR 12.x

ADR-0016 Frontend / Autenticação Aceita

Um site na Netlify por aplicação, em subdomínios

Três sites na Netlify, um por aplicação, cada um num subdomínio próprio (admin., crm., marketing.).

ADR-0018 Dados & Armazenamento Aceita

Azure Database for PostgreSQL Flexible Server, com acesso privado

Azure Database for PostgreSQL Flexible Server, com acesso privado pela VNet e sem IP público.

ADR-0019 Infraestrutura & Nuvem Aceita

Segredos no Key Vault, lidos por Managed Identity; banco sem senha

Os segredos ficam no Azure Key Vault e são lidos por Managed Identity; o banco é acessado sem senha, por autenticação Microsoft Entra com a mesma identidade.

Origem: P-15 (`C4/04-implantacao.md`) Ler Decisão
ADR-0020 Infraestrutura & Nuvem Aceita

NAT Gateway com IP de saída fixo só quando exigido

Sem NAT Gateway no início. Ele entra, na VNet que já existe, quando algum sistema externo exigir liberação por IP.

Origem: P-16 (`C4/04-implantacao.md`) Ler Decisão
ADR-0021 Infraestrutura & Nuvem Aceita

Recursos da Azure na região Brazil South

Todos os recursos da Azure do SmartCorbans ficam em Brazil South, a mesma região do sistema atual.

Origem: P-17 (`C4/04-implantacao.md`) Ler Decisão
ADR-0022 Infraestrutura & Nuvem Aceita

Homologação com a mesma forma de produção, descrita em código

Um ambiente de homologação com a mesma forma de produção, em resource group próprio, com recursos menores.

Origem: P-18 (`C4/04-implantacao.md`) Ler Decisão
ADR-0023 Dados & Armazenamento Aceita

Sem chave estrangeira entre schemas de módulos diferentes

Entre schemas de módulos diferentes, a referência é só o identificador, sem chave estrangeira. Dentro do mesmo módulo, chave estrangeira normal.

Origem: preparação do modelo de dados Ler Decisão
ADR-0024 Dados & Armazenamento Aceita

Arquivos no Azure Blob Storage privado, entregues por URL assinada

Os arquivos ficam num Azure Storage Account (Blob Storage) privado, em Brazil South.

Origem: Modelo de dados · Estrutura (`Dados/01-estrutura.md`, §6) Ler Decisão
ADR-0025 Backend & Aplicação Aceita

Tempo real nas três aplicações e sino único por usuário

O sino é único por usuário, igual nas três aplicações, e as três se conectam ao hub de tempo real.
